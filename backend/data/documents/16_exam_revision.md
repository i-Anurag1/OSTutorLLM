# Exam Revision Sheet

## Key formulas
Turnaround time = completion time - arrival time. Waiting time = turnaround time - burst time. Response time = first CPU time - arrival time. Effective access time with a TLB = h * (t + m) + (1 - h) * (t + 2m). Effective access time with page faults = (1 - p) * m + p * s. Page table entries = virtual address space / page size. Physical address in paging = frame number * page size + offset. Segmentation: physical address = base + offset if offset is less than limit. Need = Max - Allocation in the Banker's algorithm.

## Definitions to remember
A process is a program in execution. A thread is the unit of CPU scheduling within a process. A race condition is a bug where the outcome depends on the timing of concurrent accesses. A deadlock is a circular wait among processes holding resources. A page fault is a trap caused by referencing a page that is not in memory. Thrashing is excessive paging that collapses throughput. A system call is the controlled entry point from user mode into the kernel. An inode stores a file's metadata and block pointers but not its name.

## Common mistakes
Forgetting that waiting time excludes the burst time. Treating an unsafe state as if it were already a deadlock. Believing that more frames always means fewer page faults, which fails for FIFO because of Belady's anomaly. Mixing up internal fragmentation (paging, inside a block) with external fragmentation (segmentation and contiguous allocation, between blocks). Using a less-than-or-equal check against the limit in segmentation instead of a strict less-than. Forgetting to count the return jump in C-SCAN and C-LOOK when a question asks for total head movement.

## Viva questions with short answers
What is the difference between a process and a thread? A process owns an address space and resources, while threads inside it share them and differ only in stack and registers. Why does the OS need two modes? To stop user programs from executing privileged instructions that could damage other programs or the hardware. What causes starvation and how is it solved? Unfair policies such as SJF and priority can postpone a process indefinitely, and aging raises the priority of waiting processes. What are the four Coffman conditions? Mutual exclusion, hold and wait, no preemption and circular wait. Why is LRU better than FIFO? It uses recency of use, which matches locality, and it never shows Belady's anomaly. What does fork return? Zero in the child and the child's process ID in the parent. What is the benefit of a TLB? It caches page translations so most accesses avoid a second memory access for the page table.

## Choosing an algorithm in exam answers
For CPU scheduling say FCFS is simple but suffers the convoy effect, SJF is optimal for average waiting time but can starve long jobs, Round Robin gives good response time for interactive work, and priority scheduling needs aging. For page replacement say OPT is the benchmark, LRU is a good practical approximation and FIFO is cheap but can show Belady's anomaly. For disk scheduling say SSTF reduces movement but can starve, SCAN and C-SCAN avoid starvation, and LOOK variants avoid travelling to the physical end.
